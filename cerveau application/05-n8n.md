# 🔗 Brique 05 — N8N (automatisations)

**État : 🟡 Amorcé** — un **premier workflow réel** est en place : **observabilité Docker + triage IA + auto-réparation bornée** (`docker/n8n/erp-observabilite.workflow.json`, doc `docker/n8n/README.md`, ~96 lignes). Il surveille la santé des conteneurs, fait trier les incidents par Claude (`ANTHROPIC_API_KEY`, hors dépôt) et déclenche des actions correctives limitées si `AUTOHEAL_ENABLED`. Les workflows métier (Silae/Sage/sauvegarde ci-dessous) restent la **cible**.

## L'idée en une phrase
**N8N** est un outil d'automatisation **visuel** (open-source, auto-hébergé — comme Zapier mais chez toi). On y dessine des **workflows** : un **déclencheur** → des **étapes** → des **actions**, en branchant l'ERP, les mails, la base, des fichiers.

## Ce qu'on automatiserait ici (exemples concrets)
| Workflow | Déclencheur | Actions |
|---|---|---|
| **Sauvegarde nocturne** ⭐ | chaque nuit | `pg_dump` de la base → dépôt sur stockage → mail de confirmation |
| **Alerte non-conformité** | nouvelle NC en base | mail au responsable qualité |
| **Rapport KPI hebdo** | chaque lundi 7 h | lit les indicateurs → e-mail à la direction |
| **Export paie** ⭐ | fin de mois | temps pointés → fichier **Silae** |
| **Export compta** ⭐ | fin de mois | écritures → fichier **Sage (FEC)** |
| **Factures fournisseurs** | fichier déposé | lecture → insertion en base |

⭐ = exigences **go-live** déjà identifiées.

## Comment N8N se branche à l'ERP
Deux portes d'entrée (voir [🗄️ DB & API REST](03-db-et-api-rest.md)) :
1. L'**API applicative** `/api/*` (porte la règle métier) — la voie préférée.
2. L'**API PostgREST** de Supabase (accès direct aux tables) — pour le brut (ex. sauvegarde, lectures).

## ⚠️ Prérequis à prévoir
- **Authentification « machine à machine »** : N8N ne peut pas se connecter avec un **matricule + PIN** (c'est un humain, ça). Il faut une **clé de service** dédiée (un jeton), à ajouter côté backend. → petite tâche à faire **avant** la 1ʳᵉ automatisation qui écrit.
- **N8N tourne dans l'orchestre Docker** ([🐳 Docker](04-docker.md)) → cette brique dépend de la brique 04.

## Le process de travail (comment on avancera ensemble)
1. **Lister** les tâches répétitives qui valent le coup (on part des ⭐).
2. Monter N8N (une boîte dans le `compose`).
3. Créer la **clé de service** côté ERP.
4. Construire **un workflow à la fois** dans l'éditeur visuel, le tester, le documenter ici.
5. Ne jamais mettre un secret en clair dans un workflow → variables N8N.

## Quand cette brique sera construite → à maintenir
