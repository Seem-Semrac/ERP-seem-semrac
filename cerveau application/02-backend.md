# ⚙️ Brique 02 — BACKEND

**État : ✅ Fait** — la logique serveur : routage, droits, règles métier, accès aux données.

## L'idée en une phrase
Un seul programme **Hono** reçoit chaque requête, vérifie **qui a le droit**, exécute la **règle métier**, lit/écrit dans la base, puis renvoie soit une **page** (frontend), soit du **JSON** (API).

## Le trio de fichiers à connaître
| Fichier | Rôle | Lignes |
|---|---|---|
| [`src/index.tsx`](../src/index.tsx) | **Le routeur** : ~290 routes. Le point d'entrée (`export default app`). Câble chaque URL à sa page ou son handler. | 6 950 |
| [`src/queries.ts`](../src/queries.ts) | **L'accès aux données** : toutes les fonctions qui lisent/écrivent dans Supabase (ex. `upsertReferenceClient`, `createDemandeTravaux`). Aucune requête DB ailleurs. | 2 381 |
| [`src/auth.ts`](../src/auth.ts) | **Les droits (RBAC)** : 13 rôles × 15 services, login matricule+PIN, JWT, hachage PBKDF2. | 245 |

+ [`src/types.ts`](../src/types.ts) (types partagés, 1 055 l.) · [`src/db.ts`](../src/db.ts) (client Supabase) · [`src/qref.ts`](../src/qref.ts) (référentiels QHSE).

## Les droits (RBAC) — le point sensible
- **Login** : matricule + PIN → session **JWT** en cookie (PIN hachés PBKDF2, re-hash paresseux).
- **Contrôle** : `serviceFor(path)` associe chaque URL à un service ; `canAccess` décide. **Fail-closed** : une `/api/*` non mappée est refusée par défaut (corrigé lors de l'audit).
- **Activation** : `AUTH_ENFORCE=on` (off en bêta) + compte de secours `BOOTSTRAP`.
- **4 points de câblage** par service (MENU_SERVICES, PAGE_SEG_SERVICE, API_FAM_SERVICE, canAccess) → toute nouvelle route doit les respecter (skill `erp-new-module`).
- **Écriture sur un service sans exception de chemin** : `peutEcrireService(user, svc)` (`src/auth.ts`, 14/09/2026) — même règle que `canAccess` sur un POST ordinaire de la famille, **mais** sans le passe-droit self-service. Sert à revérifier dans un handler (message clair, seul contrôle quand `AUTH_ENFORCE=off`) et à juger **un autre salarié** que la personne connectée (le contrôleur d'un PV de réception). ⚠ `canAccess` répond toujours oui sur une route self-service : la réception et le PV fournisseur (`/api/expeditions/bc/:id/(receptionner|pv)`) en ont été **sortis**, ils étaient ouverts à tout compte connecté.
- **Signature d'atelier (15/09/2026)** : une route **self-service** (`SELF_SERVICE_RE`) est ouverte à **tout compte connecté** (borne partagée) — c'est donc le **handler** qui juge le salarié du matricule + PIN, jamais la personne connectée ni un nom envoyé par le navigateur. « Écriture Production » d'un autre salarié = `sessionDeSalarie` (même calcul que le login) + `peutEcrireService`. Réception d'un BDT : opérateur ou écriture Production ; soldage : opérateur qui a reçu le bon ou écriture Production (`src/soldage_bdt.ts`) ; DA et PV de non-conformité de l'atelier : écriture Production (`src/prod_da_nc.ts`). Une route sans ce contrôle n'a rien à faire dans la liste (`/api/production/non-conformites` en est sortie). Détail : [`04-auth-rbac.md`](../docs/technique/04-auth-rbac.md).
- **Confidentialité au niveau champ** : une donnée sensible peut être gardée serveur selon le droit d'écriture. Ex. le **taux horaire** de la fiche employé n'est **sérialisé côté client que si `canAccess(user,'/api/rh/salarie','POST')`** (droits d'écriture RH) ; sinon `null` — masqué (`***`), jamais dans la page. Révélé « au clic maintenu » pour les autorisés.

## Les grands flux métier (câblés dans le backend)
- **BE** : DT → **analyse BE** (`/be/analyse` déverse la nomenclature : CRU, **couverture matière/stock/seuils**, gamme identique à la nomenclature — étapes verrouillées + étapes glissables, exigences = DT, plan client ouvrable, upload GED `analyse_dt`) → **offre** (brouillon) → planning ; **répertoire réfs clients** (réf interne ↔ client ↔ réf client ↔ plan). Une **DT mixte Seem/Semrac** s'analyse en **2 volets** (un par site, chaque pièce individuelle) ; l'**offre fusionnée** n'est créée qu'aux deux volets terminés (`POST /api/dt/:id/analyse` param `site`, avancement dans la méta `sites`, sans migration).
- **Production (lot C, 14/09/2026)** : module pur `src/gamme.ts` = gamme d'un lot **et chemin critique** (l'étape suivante démarre après le réglage de la précédente ; `/affecter` cale le même jour et refuse un jour antérieur, sans jamais décaler la suite) ; `src/presences.ts` = règles des présences (4 créneaux) ; découpe (`planDecoupeBdt`, un seul porteur du réglage par famille) et recollage rejouable (`/recoller`, mises à jour conditionnelles `majBDTConditionnelle`) ; congés d'opérateur validés par la Production, jamais par soi-même. **Soldage** (15/09/2026) : la matrice de compétences n'avertit plus que (elle est indexée par **id de process**) ; transition `recu → solde` conditionnelle ; le réalisateur (`operateur_id`) n'est jamais réécrit, le soldeur est tracé à part. **Atelier → Qualité / Achats** : `POST /api/production/nc` (NC `categorie 'prod'`, statut « Ouvert », compteur continu de la Qualité, rattachement vérifié) et `POST /api/production/demande-achat-operateur` (DA « Prénom Nom (Production) »).
- **Traçabilité EN 9100** : toute écriture sur une nomenclature **validée** (fiche, gamme, fournitures, prépa technique, GED, nouvel indice, suppression) ajoute une entrée à `nomenclature_journal` — auteur tiré de la session, écarts avant → après calculés par `src/nomenclature_journal.ts` ; sans la table, la sauvegarde passe et la réponse dit `journal: false`.
- **Commercial** : offre (les **avoirs client en cours** s'affichent en **déduction → net**) → **commande** (les avoirs sont **décomptés à l'acceptation**, plus ancien d'abord → `partiel`/`cloture`) → BL (partiels) → **facture** (PDF).
- **Retour client** : NC → avoir (AV-) *ou* commande prioritaire (CMDP-) → « Lancer la production ».
- **Achats** : DA → BC → réception (BL) → PV → NC/quarantaine → **décision sur le lot** : renvoi au fournisseur, dérogation avec le fournisseur (entrée en stock, réfaction possible) ou **entrée partielle** (le reste repart ou part au rebut) — `POST /api/qualite/quarantaine/:id/decision-fournisseur`. Compensation **avoir** (registre des Achats, `avoirs_fournisseurs`) ou **remplacement** (`qte_recue` du BC décrémentée, retour en `recu_partiel`). La décision est **réservée atomiquement** (transition conditionnelle `en_cours` → décidé) avant tout effet, et chaque effet raté est **dit** dans la réponse ; le statut du BC se recalcule au même endroit pour tous (`recalculerStatutBc` : PV conforme **ou** lot tranché). Matière renvoyée sans remplacement ⇒ la porte matière **reste fermée**.
- **Mères ordonnées et sous-lots (lot H2, 18/09/2026)** : module pur `src/nomenclature_arbre.ts` (composants ordonnés = ordre de fabrication, `controlerComposants` → 409 `cycle_composants` / `profondeur_max` avant toute écriture de nomenclature, 409 `composant_utilise` à la suppression ; `developperArbre` → `planLotsArbre` → `attribuerIdsSousLots` : un sous-lot par composant, `LOT-…-ZZ.RR`, récursif, idempotent ; `opsParLot`, `lotFini`, `avancementArbre`, `vigilanceSousLots`, `vueArbreLot`) ; plan unique d'une affaire (`planProductionAffaire`) pour la cascade d'acceptation (lots, BDT/BDS `bonIdDuLot` / `cleBon`, prépa par pièce, **DA agrégées par référence**) et le déblocage proforma ; route **`POST /api/production/lot/:id/sous-lots`** (simulation, `lot_clos`, `lot_termine`, `planCompletementLot`, `porte_matiere`) ; `generer-bdt` ; vigilance « sous-lots non terminés » dans `bdtVigilance` (aucune porte nouvelle) ; `recomputeCmdAvancement` en remontant, jamais de régression d'un lot libéré, recalcul au retour d'un BDS ; **racines seulement** pour libération (409 `sous_lot_non_liberable` / `arbre_non_termine`), BL (409 `sous_lot_non_expediable`, prorata corrigé) et KPI ; journal EN 9100 des composants (`diffComposants`). Sans `cloud-14` : `lotsArbreDispo()` ⇒ mère lancée seule + avertissement.
- **Cadence usine, heures ouvrées, chevauchement, remise en goulotte (lot G, 16/09/2026)** : règles pures `src/cadence.ts` (créneaux d'un jour, calendrier d'un site ou de l'union, `ajouterHeuresOuvrees`, cadence d'un site **à une date** avec `effet`, validations) ; base `src/cadence_db.ts` (`lireDonneesCadence` → `{data, error, absente}` : **trois états**, une panne n'est jamais « tout ouvert ») ; routes `/api/production/cadence` (GET, `/calendrier`, POST `/site` avec date d'effet et `confirmation_requise`, POST `/modeles` conditionnel sur `maj_le`), écriture Production revérifiée ; présence : créneau fermé → 409 `creneau_ferme`. **Planning** : `tempsPlanning` (`src/gamme.ts`) passé en dernier argument du chemin critique (grille 5 h–23 h si cadence absente) ; `src/planning_cadence.ts` (`heureFermee` → 409 `heure_fermee`, `intervallePosteOuvre`, `ajouterPourOp`) ; `lireCadencePlanning` : panne → **503** ; `src/poste_oas.ts` : **G3** même process sur le poste → 409 + contrôle **après écriture** (course, annulation conditionnelle `updated_at`), **G4** `planRemiseGoulotte` (propagation virtuelle, reçus signalés) → 409 `successeurs_a_deprogrammer` sans `deprogrammer_successeurs`, puis `deprogrammerBDTSiInchange` (`remis_goulotte_le`) ; **G2** `oasSuivantParBdt` (badge) et `lotsAVenirOas` (page OAS). `/recu` écrit `recu_le` ; `/solder` +24 h la nuit ; `/rh/temps` horaires selon la cadence (`heuresPresence`).
- **PV quantitatif / qualitatif → Mise en stock (lot F, 15/09/2026)** : le PV (`POST /api/expeditions/bc/:id/pv`, `src/pv_reception.ts` v2) reçoit la **quantité reçue de chaque ligne** (Conforme comme Non conforme ; prévue recalculée par `qtesPrevuesPV`, 400 « rechargez » si elle a changé) ; écart de quantité sans reliquat ou excédent = quantitatif, observation = qualitatif ; **une NC fournisseur par ligne** (`type_nc` Fournisseur, `categorie`, `type_defaut`) ; quarantaine par ligne qualitative (`ligne_idx`) + certificat absent ; **excédent → `validations` `excedent_reception`** (Direction : accepter → file, refuser → quarantaine `QEXC-…` retour à expédier, conditionnel) ; **reliquat → BC `<num_bc>-R<n>`** (`bc_parent_id`, `date_a_valider`, idempotent par BL, la date d'arrivée le valide conditionnellement) ; `BL.qte` réécrite avec le reçu. **Rien n'est crédité au PV ni à la décision Qualité** : `ajouterAMettreEnStock` ajoute des lignes à la file `mises_en_stock` (idempotente par PV + ligne, BL + ligne, quarantaine + ligne, validation + ligne ; `refusees` ; `table_absente` ⇒ repli `crediterLignesRepli`). **Stock** (`/api/stock/…`, écriture Stock revérifiée) : `mise-en-stock/:id/accepter` (réservation conditionnelle `a_ranger → range`, référence créée / complétée, emplacement **fixe** historisé, crédit conditionnel + mouvement lié par index unique, remise en état si le mouvement échoue), `annuler`, `entree` (→ file), `sortie` (BDT relu, lot imputé), `ajustement` (écart signé), `types-objet`, `zones`, `:id/emplacement` (+ historique). **Porte matière au rangement** : `ouvrirPorteMatiere` (lectures strictes, aucune ligne à ranger, BC de reliquat ≠ rachat, compensation `aucune` ≠ manque) → `EtatPorteMatiere`. Décision Qualité : `lignesDeQuarantaine` + `repartirPartAcceptee` (répartition exigée sur plusieurs articles, avant réservation). `quantitesARangerParRef` (panne ≠ vide) dans DA du manque, `generer-da`, réappro auto, `scan-alertes`, cockpit, `kpi.ts`. Règles pures `src/mise_en_stock.ts`.
- **Réception fournisseur → PV (lot D, 14/09/2026)** : `POST /api/expeditions/bc/:id/receptionner` — N° de commande et de BL fournisseur obligatoires, bloc **hors France** (poids, nomenclature douane, code EWX 1|2, mode d'arrivée), **quantité du BL = reste à recevoir** (`src/reception.ts` : `planReception`, jamais 0, `null` = inconnue ; exceptions livraison partielle / BC sans quantité) ; le BC est écrit **conditionnellement avant** le BL, remis en état si le BL échoue, BL **relu** sur une erreur sans code. `POST /api/expeditions/bl/:id/reception-infos` corrige les 7 informations sans toucher quantité ni stock. `POST /api/expeditions/bc/:id/pv` (`src/pv_reception.ts`) : le serveur **relit les lignes du BC** (le client n'envoie que `{idx, conforme, observation}`), revérifie le contrôleur (salarié actif ayant l'écriture Expéditions, droits recalculés comme au login), refuse un conforme sans certificat exigé et un PV ouvert avant un changement d'exigence (409 `certificat_change`) ; non conforme → NC détaillée + quarantaine ; conforme → entrée en stock **ligne par ligne** pour un BC à plusieurs articles (`repartitionStockMultiArticles`). Exigence de certificat portée par le BC (`src/certificat_matiere.ts`, `POST /api/achats/bc/:id/certificat-matiere`, verrouillée par un PV conforme).
- **Avoirs fournisseurs** : `POST /api/achats/avoirs-fournisseurs` (+ `/recu`, `/imputer`, `/annuler`) — cycle à recevoir → reçu → partiel → soldé, annulation motivée, jamais de suppression ; transitions **conditionnelles** (statut et montant imputé attendus) pour qu'un euro ne soit pas imputé deux fois.
- **Coût de revient** (14/09/2026) : **seul le process machine porte un taux horaire** (`process_atelier.taux_horaire_machine`, saisi à la main) ; le taux homme est le **coût chargé RH** (`salaries.taux_horaire_charge` : moyenne du site pour un coût estimé, opérateur du BDT pour un coût réel). Règle unique dans `src/shared.ts` — `etapeDecomp` (ROP → homme ; RGM → homme + machine ; THV → homme ; TMV → machine, sur process machine seulement), `computeNomCostForQty(nom, fournitures, q, { taux, site })`, `coutReelBdt(b, tx, salById)` — alimentée par `getTauxAtelier()` (`src/queries.ts`), qui **remonte** l'échec de lecture : les routes refusent alors de chiffrer (503) ou rendent des coûts `null` plutôt qu'un 0 trompeur. Transition tant que la base n'a pas la colonne : taux lu sur `machines.cout_h`.
- **Stock** : toute **nouvelle référence de catalogue** (`produits_fournisseurs`) crée une **entrée `stock` vide** automatiquement (idempotent) — le stock reflète le catalogue, se remplit via les BL.
- **Qualité** : NC → 8D ; contrôles cotes → Cp/Cpk ; dérogations. **Portes qualité** : un BL est **bloqué (409)** si NC/quarantaine.

## Quand cette brique change → à maintenir
1. Nouvelle route → câbler les **4 points RBAC** + `queries.ts` (jamais de requête DB dans une page).
2. `npm run verify` (tsc + build + harnais) **vert** avant commit.
3. Mettre à jour [`docs/technique/07-api-reference.md`](../docs/technique/07-api-reference.md) (généré) et cette page si une famille de routes apparaît.
